# OctoAcme Project Management Docs

OctoAcme uses a customer-first, iterative approach to deliver measurable value. Projects have clear ownership, use data to guide decisions, and make space for candid feedback and learning.

## Project lifecycle

1. **Initiate:** Define the problem, measurable outcomes, stakeholders, timeline, and initial risks in a project one-pager. Confirm alignment and team availability before planning.
2. **Plan:** Break approved work into prioritized, shippable increments. Agree on acceptance criteria, estimates, Definition of Done, dependencies, milestones, and a release plan.
3. **Execute and track:** Manage work on a project board, deliver and review small increments, test against acceptance criteria, and monitor progress and outcome metrics. Keep risks visible and escalate blockers through the PM and product leadership.
4. **Release:** Verify acceptance criteria, CI and security scans, release notes, smoke tests, and rollback plans; deploy and communicate the outcome to stakeholders.
5. **Improve:** Hold retrospectives after sprints, releases, milestones, and incidents. Assign owners and due dates to a small set of improvement actions and follow up on their impact.

The Project Manager coordinates delivery, schedules, risks, and communication; the Product Manager owns outcomes and prioritization; developers and QA deliver and validate the work; and stakeholders provide input and approvals. Core artifacts include the project one-pager, roadmap and release plan, iteration backlog, acceptance criteria and Definition of Done, risk register, and retrospective actions.

Teams use daily standups, a weekly PM/Product Manager sync and delivery update, sprint or milestone demos, and regular stakeholder updates (typically monthly or milestone-based). Escalations happen as needed.
